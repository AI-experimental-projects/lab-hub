## Architecture

```
                     lab.beaiapp.com
internet ──▶ Cloudflare ──tunnel──▶ cloudflared ──▶ web (Next.js) ──▶ SQLite (PVC)
                                     (k3s)            │
                                                      └─ collector: every 5 min fetches
                                                         each project's /status (public https)
```

The Hub **pulls** data; projects never push anything to it. Connecting a new project means adding its `lab.yaml`, and if the Hub goes down, no project notices.

| Piece | Choice | Why |
|---|---|---|
| Site | Next.js 16 (App Router, Cache Components) | Static pages regenerated every minute |
| Data | SQLite (`node:sqlite`) on a local volume | One node, zero operations |
| Collector | Inside the same server (`instrumentation.ts`) | No extra service and no public endpoint to trigger it |
| Hosting | k3s on a homelab + Cloudflare Tunnel | $0 and no open ports at home |
| Deploys | GitOps with Flux | GitHub never connects to the cluster |

## Deploys

Every push to `main` goes through contract validation, tests, lint and build. CI publishes the image `ghcr.io/ai-experimental-projects/lab-hub:sha-<commit>` and commits the new tag. Flux, inside the cluster, picks it up and rolls it out. The `version` in `/status` is that commit.

## Security

- **Network:** default-deny NetworkPolicies. The site only receives traffic from the tunnel and only goes out to DNS and public HTTPS.
- **Pods:** Pod Security `restricted`: no root, no capabilities, read-only filesystem.
- **Collector:** protected against SSRF in three layers (contract, DNS check with a pinned socket, and network).
- **Deploys:** Flux only has permissions in two namespaces. `main` is protected by rulesets.

Details in [docs/security.md](https://github.com/AI-experimental-projects/lab-hub/blob/main/docs/security.md).
